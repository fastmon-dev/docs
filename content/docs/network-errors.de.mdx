Network Error Logging (NEL) meldet die Requests, die im Browser deiner Besucher scheitern: DNS-Fehler, abgelehnte Verbindungen, Timeouts, TLS-Fehler und 4xx- oder 5xx-Antworten.

<Callout type="info" title="Nur Chromium">
  Reports schicken Chrome, Edge, Opera, Samsung Internet und andere Chromium-Browser. Safari und Firefox schicken keine, jede Zahl ist also eine Untergrenze.
</Callout>

## Einrichten [#setup]

1. Kopiere den `collector_hash` der Application. Er steht in jedem Beacon-Request hinter `/c/` und ist ein Feld der Application in der API.
2. Setze die beiden [Header](#headers) auf jede HTTPS-Antwort jedes Hosts.
3. Prüfe, dass jeder Host mit den Headern eine Site dieser Application ist oder eine Subdomain davon.
4. [Prüfe](#verify), dass ein Report ankommt.

Ein Report für einen Host, der keine Site der Application ist, wird verworfen. Ein Report legt nie eine Site an. `www.shop.example` zählt für `shop.example`, `notshop.example` nicht.

## Die Header [#headers]

```http
Report-To: {"group":"fastmon","max_age":86400,"endpoints":[{"url":"https://fastmon.site/c/n/YOUR_COLLECTOR_HASH"}]}
NEL: {"report_to":"fastmon","max_age":86400,"success_fraction":0,"failure_fraction":1}
```

Hat die Application einen eigenen [Collector-Endpoint](/de/tracker#collector-endpoint), steht dessen Host statt `fastmon.site` in der URL.

| Feld | Header | Wert | Wirkung |
| --- | --- | --- | --- |
| `group` / `report_to` | beide | `fastmon` | Verbindet die beiden Header. Der Name ist frei, er muss nur in beiden gleich sein. |
| `max_age` | `Report-To` | `86400` | So lange behält der Browser den Endpoint, in Sekunden. Mindestens so lang wie im `NEL`-Header. |
| `url` | `Report-To` | `https://fastmon.site/c/n/{collector_hash}` | Wohin die Reports gehen. |
| `max_age` | `NEL` | `86400` | So lange bleibt die Policy im Browser. Jede Antwort erneuert sie. |
| `success_fraction` | `NEL` | `0` | Anteil erfolgreicher Requests, die gemeldet werden. fastmon verwirft diese Reports. |
| `failure_fraction` | `NEL` | `1` | Anteil fehlgeschlagener Requests, die gemeldet werden. Unter `1` zählt jede Zeile `1 / failure_fraction`, und seltene Fehler können ganz fehlen. |

Wo du sie setzt:

- **Auf jede Antwort**, auch auf Fehlerseiten. Hängt die Site an [mehreren Adressen](#several-addresses), geht eine Fehlerseite ohne Header verloren.
- **Am äußersten Server, den du kontrollierst.** Den 502 von Ingress oder Load Balancer sieht die Anwendung nie.
- **Nur über HTTPS.** Eine Policy aus einer HTTP-Antwort ignoriert der Browser.
- **Auf jedem Host.** `www.shop.example` und `shop.example` sind zwei Policies.

### Beispiele [#examples]

<Tabs items={['nginx', 'Caddy', 'Apache', 'PHP']}>
<Tab value="nginx">

```nginx
server {
    listen 443 ssl;
    server_name shop.example;

    add_header Report-To '{"group":"fastmon","max_age":86400,"endpoints":[{"url":"https://fastmon.site/c/n/YOUR_COLLECTOR_HASH"}]}' always;
    add_header NEL '{"report_to":"fastmon","max_age":86400,"success_fraction":0,"failure_fraction":1}' always;
}
```

Mit `always` landen die Header auch auf Fehlerantworten. Ein `location`-Block mit eigenem `add_header` erbt nichts aus `server`, dort brauchst du beide Zeilen noch einmal.

</Tab>
<Tab value="Caddy">

```txt
shop.example {
	header Report-To `{"group":"fastmon","max_age":86400,"endpoints":[{"url":"https://fastmon.site/c/n/YOUR_COLLECTOR_HASH"}]}`
	header NEL `{"report_to":"fastmon","max_age":86400,"success_fraction":0,"failure_fraction":1}`
}
```

Die Backticks lassen die Anführungszeichen im JSON stehen.

</Tab>
<Tab value="Apache">

```apache
<IfModule mod_headers.c>
    Header always set Report-To '{"group":"fastmon","max_age":86400,"endpoints":[{"url":"https://fastmon.site/c/n/YOUR_COLLECTOR_HASH"}]}'
    Header always set NEL '{"report_to":"fastmon","max_age":86400,"success_fraction":0,"failure_fraction":1}'
</IfModule>
```

</Tab>
<Tab value="PHP">

```php
header('Report-To: {"group":"fastmon","max_age":86400,"endpoints":[{"url":"https://fastmon.site/c/n/YOUR_COLLECTOR_HASH"}]}');
header('NEL: {"report_to":"fastmon","max_age":86400,"success_fraction":0,"failure_fraction":1}');
```

Das deckt nur die Antworten ab, die PHP schreibt. Wenn du an den Webserver kommst, setz die Header dort.

</Tab>

### `include_subdomains` [#include-subdomains]

Mit `"include_subdomains":true` im `NEL`-Header gilt die Policy für jede Subdomain des Hosts. Für diese Subdomains meldet der Browser nur DNS-Fehler. fastmon behält so einen Report, wenn die Subdomain eine Site der Application ist oder eine Subdomain der einzigen Site. Eine Subdomain mit eigenen Antworten bekommt besser eigene Header.

## Prüfen [#verify]

1. **Die Header kommen an.** Schau im Netzwerk-Tab des Browsers bei einer beliebigen Antwort des Hosts nach `Report-To` und `NEL`.
2. **Ein Report geht raus.** Lade eine Seite in Chrome und ruf dann einen Pfad auf, den es nicht gibt. Auch der 404 muss beide Header tragen. Chrome schickt nach etwa einer Minute einen `http.error`-Report.
3. **Der Endpoint antwortet.** Teste ihn ohne Browser, mit einer registrierten Site statt `shop.example`:

```sh
curl -i https://fastmon.site/c/n/YOUR_COLLECTOR_HASH \
  -H 'Content-Type: application/reports+json' \
  --data '[{"age":0,"type":"network-error","url":"https://shop.example/missing","body":{"type":"http.error","phase":"application","status_code":404,"elapsed_time":12,"method":"GET","protocol":"http/1.1","referrer":"","sampling_fraction":1}}]'
```

Der Endpoint antwortet mit 204, egal ob er den Report behält oder verwirft. Den letzten Report jeder Site zeigt die Karte **Seiten und Hosts** im [Dashboard](#dashboard).

## Stolperfallen [#traps]

- **Cloudflare ersetzt deine Header**, wenn dort die eigene Network-Error-Logging-Einstellung an ist. Schalte sie für die Zone ab.
- **Shopify-Storefronts** erlauben keine eigenen Response-Header, ein Shopify-Shop kann also keine Policy schicken.
- **`Report-To` bleibt Pflicht.** Chromium liest für NEL keinen `Reporting-Endpoints`-Header.
- **Jede Application hat ihren eigenen Hash.** Ein Report für eine Site einer anderen Application wird verworfen, auch in derselben Organisation.
- **Nach einer Hash-Rotation kommen keine Reports mehr**, ohne Warnung. Trag den neuen `collector_hash` in `Report-To` ein.
- **Ein [First-Party-Proxy](/de/guides/first-party-proxy)** muss `/c/n/` und den `OPTIONS`-Preflight des Browsers durchreichen. Ein `location /c/`-Block deckt beides ab.
- **Header entfernen entfernt die Policy nicht.** Browser melden bis zu `max_age` Sekunden weiter. Willst du früher Schluss machen, schick vorher einen Tag lang `NEL` mit `"max_age":0`.

## Die Seite Netzwerkfehler [#dashboard]

Die Seite liegt in der Sidebar unter **Fehler → Netzwerkfehler**. Sie hat drei Tabs, der Tab steht in der URL.

- **Übersicht**: die HTTP-Fehler des Servers, 5xx oben, 4xx darunter. **Betroffene Besucher** steht bei jeder Zahl vorn, die Reports danach. Das Diagramm stapelt **Nach Klasse** oder **Nach Code**.
- **Wo sie scheitern**: eine Karte pro Dimension, alle auf einmal. Statuscodes, Seiten, Serveradressen, Länder, Seiten und Hosts, Geräte, Browser, OS, Traffic und Versionen, sobald ein Browser gefiltert ist.
- **Seiten und Hosts** ist zugleich der Setup-Check. Jede Site zeigt ihren letzten Report, und zeigen die meisten Reports ohne Details auf eine Serveradresse, nennt die Karte sie als wahrscheinlich ausgefallen.
- **Verbindungsfehler**: standardmäßig zugeklappt. Jeder Typ wird mit seinem üblichen Niveau verglichen, markiert werden ein kaputtes Zertifikat und ein Anstieg bei abgelehnten Verbindungen, Timeouts oder unbekannten Hosts.
- **Pfade**: erst die Hosts, darin jeweils ihre Pfade.
- **Reports**: jeder Report, der neueste zuerst, aufklappbar mit allen gespeicherten Feldern. Mehrere Reports eines Typs von einem Besucher auf einer Seite hintereinander stehen als eine Zeile da. Speichert die Site eine Besucher-ID, verlinkt der Report auf die Journey des Besuchers.

**Filtern** geht wie auf den anderen Seiten: `+` neben einem Wert filtert darauf, `-` schließt ihn aus. Die Filter der Seite (Status, Fehlertyp, Host, Pfad, Seite, Serveradresse) stehen im Filter-Panel unter **Nur auf dieser Seite** und bleiben in der URL. **Abgebrochene Ladevorgänge** sind ausgeblendet, auf der Seite und in der Journey eines Besuchers, jeweils mit einem Schalter zum Einblenden.

Die Journey eines Besuchers unter [Visitors](/de/analytics#visitors) zeigt seine fehlgeschlagenen Requests zwischen den Seitenaufrufen, in zeitlicher Reihenfolge.

## Klassen [#classes]

Jeder Report hat eine Klasse, `network_error_class`, abgeleitet aus seinem Typ.

| Klasse | Typen | Bedeutung |
| --- | --- | --- |
| `http_error` | `http.error` | Dein Server hat mit 4xx oder 5xx geantwortet. |
| `connection` | `dns.*`, `tcp.*`, `tls.*`, `h2.*`, `h3.*`, `http.response.*`, `unknown` | Keine brauchbare Antwort. |
| `abandoned` | `abandoned` | Der Request wurde abgebrochen, meist weil der Besucher weg ist, während er noch lud. |
| `downgraded` | `dns.address_changed` | Der Browser hat den echten Typ verborgen. Siehe [mehrere Adressen](#several-addresses). |
| `other` | alles andere | Ein Typ, den bisher kein Browser geschickt hat. |

## Fehlertypen [#error-types]

Die Typen, die dir am häufigsten begegnen. In den Details jedes Reports steht der Typ des Browsers, im Dashboard ein lesbarer Name.

| Typ | Was passiert ist | Wiederholt der Browser |
| --- | --- | --- |
| `http.error` | Der Server hat mit 4xx oder 5xx geantwortet. | nur 408 auf einer wiederverwendeten HTTP/1.1-Verbindung und 421 |
| `dns.name_not_resolved` | Das DNS kennt keine Adresse für den Host. | nein |
| `dns.failed`, `dns.timed_out` | Die Namensauflösung ist fehlgeschlagen oder hat zu lange gedauert. | nein |
| `dns.address_changed` | Ein Fehler, dessen Typ der Browser verborgen hat. | wie der verborgene Typ |
| `tcp.refused` | Der Server hat die Verbindung abgelehnt. | nein |
| `tcp.timed_out` | Verbindung oder Request hat zu lange gedauert. | nein |
| `tcp.reset`, `tcp.closed`, `tcp.aborted` | Die Verbindung ist abgerissen. | auf einer wiederverwendeten Verbindung |
| `tls.cert.*` | Das Zertifikat ist ungültig, abgelaufen, nicht vertrauenswürdig, widerrufen oder für einen anderen Host. | nein |
| `tls.version_or_cipher_mismatch` | Browser und Server haben keine gemeinsame TLS-Version oder Cipher. | nein |
| `h2.ping_failed` | Die HTTP/2-Verbindung antwortet nicht mehr. | bis zu zweimal |
| `http.response.*` | Die Antwort war nicht lesbar, etwa leer oder abgeschnitten. | teils, auf einer wiederverwendeten Verbindung |
| `abandoned` | Der Request wurde vor dem Ende abgebrochen. | nein |
| `unknown` | Ein Browserfehler ohne eigenen Namen, die Ursache ist verloren. | teils |

## Einen Report lesen [#reading]

- **`http.error`** ist der einzige Typ, der sagt, dass dein Server mit einem Fehler geantwortet hat. Er gilt für jeden Request an den Origin, auch für Bilder und API-Calls.
- **`tls.cert.*`, `tls.version_or_cipher_mismatch` und `http.response.*`** deuten ebenfalls auf deine Seite.
- **`abandoned`, `tcp.reset`, `tcp.closed`, `tcp.aborted`, `h2.ping_failed` und `unknown`** sind ein Grundrauschen, das jede Site hat. Besucher gehen, während noch etwas lädt, und Mobilfunknetze verlieren Verbindungen.
- **Ein plötzlicher Anstieg von `tcp.refused` oder `tcp.timed_out`** heißt, dass der Server keine Verbindungen mehr annimmt oder beantwortet.
- **Ein Report beweist nicht, dass ein Besucher den Fehler gesehen hat.** Bei manchen Typen meldet der Browser zuerst und schickt den Request dann erneut, oft mit Erfolg. Ein Fehler kann außerdem mehrere Reports hinterlassen.

## Sites hinter mehreren Adressen [#several-addresses]

Zwei Ingress-Knoten, ein CDN oder IPv4 neben IPv6 legen mehrere Adressen hinter einen Namen. Der Browser speichert die Policy zusammen mit der Adresse, von der sie kam. Fällt eine Adresse aus, schickt nur noch die andere die Policy, und die Fehler der toten Adresse kommen als `dns.address_changed` ohne Status und Dauer an.

- **Steigt die Klasse `downgraded`** auf so einer Site, fällt eine Adresse aus.
- **`server_ip`** nennt die Adresse, an die ein Request ging. Die Karte **Serveradressen** oder eine Aufschlüsselung der `downgraded`-Reports nach `server_ip` zeigt die ausgefallene.
- **Eine Fehlerseite ohne Header** von der anderen Adresse geht verloren, der Ingress muss sie also auf jede Antwort setzen. Prüf das an einem 404, wie unter [Prüfen](#verify).

Gespeichert wird nur eine öffentliche `server_ip`. Siehe [Datenschutz → Network-Error-Reports](/de/privacy#network-error-reports).

## Grenzen [#limits]

- **Nur Chromium-Browser.** Jede Zahl ist eine Untergrenze.
- **Besucherzahlen brauchen [`store_stitch`](/de/tracker#store-stitch).** Eine Site ohne zählt bei den Reports mit, nicht aber bei **Betroffene Besucher**, und die Seite nennt sie.
- **Eine kleinere `failure_fraction`** macht die Besucherzahl zur Untergrenze.
- **Ein Netzwechsel trennt den Besucher.** Ein Report bekommt seine Besucher-ID beim Upload, ein Report aus einem neuen Netz passt also nie zu den Seitenaufrufen davor.
- **Die ID rotiert täglich.** Ein Report, der nach der Rotation hochgeladen wird, kann bei einem neuen Besucher landen.

## API [#api]

Alle drei Routen nehmen dieselben `filters`, darunter `error_type`, `network_error_class`, `status_code_range`, `server_ip`, `host`, `path` und `page_url` samt `exclude`. Jede andere Analytics-Route lehnt diese Filter mit 422 ab.

| Route | Liefert |
| --- | --- |
| [`POST /analytics/network-errors`](/de/api/analytics/queryAnalyticsNetworkErrors) | Anzahl, Zeitreihe, Fehlertypen, Statuscodes, Zeit bis zum Fehler und die Top-Pfade pro Host |
| [`POST /analytics/network-errors/breakdown`](/de/api/analytics/queryAnalyticsNetworkErrorsBreakdown) | Reports nach einer `dimension` gruppiert, mit Anteil und Besuchern |
| [`POST /analytics/network-errors/reports`](/de/api/analytics/listAnalyticsNetworkErrorReports) | Einzelne Reports, der neueste zuerst, seitenweise per `cursor` |

Die Zählungen sind mit `1 / failure_fraction` gewichtet, einzelne Reports nicht. Ohne `error_type`-Filter zählt jeder Typ mit, auch `abandoned`. [Visitor-Detail](/de/api/analytics/getAnalyticsVisitorDetail) und [Checkout-Journeys](/de/api/analytics/queryAnalyticsCheckoutJourneys) liefern `network_errors` neben `pages` und `events`: fehlt das Feld, wurde nicht nachgesehen, `[]` heißt keine Reports.
