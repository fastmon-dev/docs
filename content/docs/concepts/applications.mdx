An **application** is the tracking embed. It serves one or many
domains, each a **site**.

The hierarchy is **Organization → Application → Site**:

- An **organization** owns applications, members, and tokens.
- An **application** owns the snippet and all collection config.
- A **site** is a single domain under the application, with its own
  dashboard. See [Sites](/en/concepts/sites).

## The two hashes

An application has two short hashes:

- **`source_hash`** sits in the **script URL** (`/s/{source_hash}.js`)
  and picks the bundle to ship to the browser.
- **`collector_hash`** sits in the **ingest URL** (`/c/{collector_hash}`)
  and says which application a beacon belongs to. It's baked into the
  script.

Both are on the application's card under **··· → IDs & hashes**.
Rotating them regenerates both, invalidates the served script, and
breaks a pasted [Shopify pixel](/en/guides/shopify-checkout).

## What gets collected: presets

The collection config lives on the application: a
[preset](/en/tracker) (`minimal` / `standard` / `full`, default
`standard`) that expands into individual flags, all baked into the
served bundle.

## Where beacons go: the collector

`collector_mode` decides the host in the snippet:

- **`default`**: fastmon's shared collector (`fastmon.site`);
  third-party to your site.
- **`relative`**: host-less `/s/` and `/c/` paths, served
  same-origin via your reverse proxy; first-party.
- **`custom`**: an absolute `collector_endpoint` host you control.

It's set at create time. See
[Implementation](/en/install/html).

## Unknown domains: `site_policy`

When a beacon arrives from a hostname that isn't a registered site,
**`site_policy`** decides:

- **`open`** (default): the beacon is dropped and the hostname is
  recorded as a **suggested domain** you can adopt in one click.
- **`auto`**: a site is created for the hostname and its traffic is
  kept from then on.
- **`strict`**: the beacon is dropped with no suggestion; only
  registered domains are served.

## Environment

`environment` marks an application **`prod`** or **`dev`** (default
`prod`). Use `dev` to keep staging and preview apps out of your
production traffic.

## Platform, shop, and SPA

`platform` names the shop system or CMS the application runs on, for
example `shopware6`, `shopify`, or `prestashop`. A platform you set
yourself is `manual`, and later detection leaves it alone.

`shop.active` says whether the application is a shop, with
`shop.source` for where that came from. Without a setting it follows
the platform; an unknown platform leaves it `null`. `spa` marks a
single-page app and is set by hand.

A Shopify application also serves the [checkout event
pixel](/en/guides/shopify-checkout), built from `source_hash` and the
collector settings.

## Page-type detection

`platform` says what the application runs
on; `page_type.body_class` turns on reading the page type
(home, product, cart, checkout) from the page's `<body>` class.
Picking a platform does not turn the read on, and it stays off for
Shopify and PrestaShop, which have no ruleset. Server-Timing always
wins over the body-class read.

A theme that renamed those classes records nothing, so
`pagetype_rules` names your own: up to 24 exact class names, each
mapped to a page type. The rules are read before the ruleset and work
without one. Two endpoints propose what to set and write nothing:
[`detect-pagetype`](/en/api/applications/detectApplicationPageType)
names the shop system,
[`pagetype/discover`](/en/api/applications/discoverApplicationPageTypeRules)
works out the class names. See
[Tracker → `pagetype_rules`](/en/tracker#pagetype-rules).

## Checkout funnel [#checkout-funnel]

On by default, under `shop.checkout`. The collector marks each
pageview whose URL matches a cart, checkout, or success pattern, and
records the cart requests the shop's pages send via fetch/XHR.
`checkout_tracking` is the opt-out; the three path lists each inherit
the built-in patterns (`null`) or replace them wholesale. Marking is
forward-only, and counting visitors per stage needs `store_stitch`.
See [Checkout
funnel](/en/checkout-funnel).

## Traffic sampling [#sampling]

`collection.sampling_rate` stores a share of your visitors instead of all
of them. The default is `1.0`, and the API refuses a rate below `0.1`.
The edge keeps or drops a visitor's pageviews together, and a new
rate applies within about a minute.

Pageviews, visitors, and error counts are scaled back up. Percentiles,
shares, minimum-sample thresholds, the Beacon explorer, funnel stage
counts, and histograms stay on the stored rows. Only an application that
stores `stitch` is sampled, checkout events never are, and every
analytics response reports the setting in `meta.sampling`.

```json
PATCH /applications/{app_id}
{ "collection": { "sampling_rate": 0.5 } }
```

## Per-domain defaults

Three settings are application-level **defaults** that each member
site inherits and can override per domain:

- **`data_retention_days`** (default `90`): how long raw data is
  kept.
- **`store_stitch`**: persist the edge visitor `stitch`, which drives
  unique-visitor counts.
- **`count_visitors_by`** (`stitch` / `session`): which identifier the
  **visitors** metric counts by. Clamped at query time to what the
  site stores. See
[Sites](/en/concepts/sites).

## What's on an application [#application-fields]

The response groups its fields into `page_type`, `shop`, `collection`,
`collector`, `script`, and `site_defaults`. Create and update take the same
groups as partial objects, and reject any key they do not know. The flat
twins these groups replaced no longer answer.

| Field                        | Type              | Notes                                                                 |
| ---------------------------- | ----------------- | --------------------------------------------------------------------- |
| `id`                         | UUID v7           | Stable identifier.                                                    |
| `organization_id`            | UUID v7           | The owning organization.                                              |
| `name`                       | string            | How the application appears in the UI.                                |
| `environment`                | enum              | `prod` or `dev`. Default `prod`.                                       |
| `platform`                   | object · nullable | Shop system or CMS: `key`, `source`, `detected_via`, `detected_at`.   |
| `shop.active`                | bool · nullable   | Whether this is a shop. `null` follows the platform.                  |
| `spa`                        | bool              | Single-page app. Set by hand, default `false`.                        |
| `collection.*`               | bool · enum       | The preset flags: sessions, fetch/XHR, error messages and frames, query keys and values, `session_consent`, `template_url_ids`. See [Presets](/en/tracker). |
| `collection.sampling_rate`   | number            | Share of visitors stored, `0.1` to `1.0`, default `1.0`. See [Traffic sampling](#sampling). |
| `page_type.body_class`       | bool              | Read the page type from the `<body>` class. Off by default.           |
| `page_type.rules`            | list · nullable   | Your own body classes mapped to page types. Read before the ruleset.  |
| `shop.checkout.tracking`     | bool              | Checkout funnel on (`true`, the default) or off. See [Checkout funnel](#checkout-funnel). |
| `shop.checkout.*_paths`      | list · nullable   | URL patterns per funnel stage. `null` inherits the built-in patterns; a list replaces them. |
| `collector.mode`             | enum              | `default` / `relative` / `custom`.                                    |
| `collector.endpoint`         | string · nullable | Custom collector host (only for `custom`).                            |
| `collector.proxy_secret`     | object            | The shared secret for a [first-party proxy](/en/guides/first-party-proxy). |
| `script.source_hash`         | string            | Globally unique; in the script URL (`/s/{source_hash}.js`).           |
| `script.collector_hash`      | string            | Globally unique; in the ingest URL (`/c/{collector_hash}`).           |
| `script.source_version`      | string            | Pinned beacon template version (`v1`).                                |
| `site_defaults.*`            | int · bool · enum | `data_retention_days`, `store_stitch`, `count_visitors_by`. A site can override each. |
| `site_policy`                | enum              | `open` / `auto` / `strict`. Unknown-hostname handling.                |
| `is_active`                  | bool              | When false, beacons are accepted but not written.                     |

Six fields stay flat for the Shopware plugin: `source_hash`,
`collector_hash`, `proxy_secret`, `collector_mode`, `collector_endpoint`
and `pagetype_ruleset`.

## Sites: adopt, move, delete

- **Add a domain**: create a site, or adopt a suggested domain.
- **Move a site**: it takes on the new application's config. A domain
  always belongs to exactly one application.
- **Delete a site**: removes that domain's data, with a confirmation.
