Eine **Application** ist der Tracking-Embed: ein Snippet, ein Satz
Erfassungseinstellungen, zwei Hashes. Sie bedient eine oder viele
Domains, jede davon eine **Site**. Die meisten brauchen eine
Application mit einer Site.

Die Hierarchie ist **Organization → Application → Site**:

- Eine **Organization** besitzt Applications, Members und Tokens.
- Eine **Application** besitzt das ausgelieferte
  `/s/{source_hash}.js`-Bundle, die komplette Erfassungs-Config und
  den `collector_hash`, an den Beacons posten.
- Eine **Site** ist eine einzelne Domain unter der Application, mit
  eigenem Dashboard. Siehe [Sites](/de/concepts/sites).

## Die zwei Hashes

Eine Application hat zwei kurze Hashes, beide auf der Application:

- **`source_hash`** steht in der **Script-URL** (`/s/{source_hash}.js`)
  und wählt das Bundle, das an den Browser geht.
- **`collector_hash`** steht in der **Ingest-URL** (`/c/{collector_hash}`)
  und sagt, zu welcher Application ein Beacon gehört. Er ist im Script
  eingebacken.

Beide findest du auf der Karte der Application unter
**··· → IDs & Hashes**. Beim Rotieren werden beide neu erzeugt, das
ausgelieferte Script wird invalidiert, und ein eingefügtes
[Shopify-Pixel](/de/guides/shopify-checkout) geht kaputt.

## Was erfasst wird: Presets

Die Erfassungs-Config lebt auf der Application: ein
[Preset](/de/tracker) (`minimal` / `standard` / `full`, Default
`standard`), das sich in Einzelflags entfaltet, alle ins
ausgelieferte Bundle gebacken.

## Wohin die Beacons gehen: der Collector

`collector_mode` bestimmt den Host im Snippet:

- **`default`**: fastmons geteilter Collector (`fastmon.site`); aus
  Sicht deiner Seite Third-Party.
- **`relative`**: hostlose `/s/`- und `/c/`-Pfade, same-origin über
  deinen Reverse-Proxy ausgeliefert; First-Party.
- **`custom`**: ein absoluter `collector_endpoint`-Host, den du
  kontrollierst.

Den Collector später zu wählen hieße, das schon eingebettete Snippet
zu tauschen. Deshalb wird er beim Anlegen gesetzt. Siehe
[Implementierung](/de/install/html).

## Unbekannte Domains: `site_policy`

Kommt ein Beacon von einem Hostnamen, der keine registrierte Site
ist, entscheidet die **`site_policy`**:

- **`open`** (Default): der Beacon wird verworfen, der Hostname aber
  als **vorgeschlagene Domain** vermerkt, die du mit einem Klick
  adoptierst.
- **`auto`**: für den Hostnamen wird eine Site angelegt, ihr Traffic
  wird ab dann behalten.
- **`strict`**: der Beacon wird verworfen, ohne Vorschlag; nur
  registrierte Domains werden bedient.

Mit `strict` nagelst du den Ingest auf registrierte Domains fest.

## Environment

`environment` markiert eine Application als **`prod`** oder **`dev`**
(Default `prod`). Nutze `dev`, um Staging und Preview aus deinem
Produktions-Traffic herauszuhalten.

## Plattform, Shop und SPA

`platform` nennt das Shopsystem oder CMS, auf dem die Application
läuft, etwa `shopware6`, `shopify` oder `prestashop`. Eine selbst
gesetzte Plattform ist `manual` und wird von späterer Erkennung nicht
überschrieben.

`shop.active` sagt, ob die Application ein Shop ist, dazu
`shop.source` für die Herkunft. Ohne Einstellung folgt der Wert der
Plattform; bei unbekannter Plattform bleibt er `null`. `spa` markiert
eine Single-Page-App und wird von Hand gesetzt.

Eine Shopify-Application liefert zusätzlich das
[Checkout-Event-Pixel](/de/guides/shopify-checkout) aus, gebaut aus
`source_hash` und den Collector-Einstellungen.

## Page-Type-Detection

Zwei unabhängige Einstellungen. `platform` sagt, worauf die
Application läuft; `page_type.body_class` schaltet das Lesen des
Page-Types (Home, Product, Cart, Checkout) aus der `<body>`-Klasse
ein. Eine Plattform zu wählen schaltet das Lesen nicht ein, und für
Shopify und PrestaShop bleibt es aus, weil es für sie kein Ruleset
gibt. `pagetype_ruleset` liest und schreibt weiter, abgeleitet aus
beiden. Server-Timing hat immer Vorrang vor der Body-Class.

Ein Theme, das eine dieser Klassen umbenannt hat, erfasst nichts.
`pagetype_rules` benennt deine eigenen: bis zu 24 exakte Klassennamen,
jeder auf einen Page-Type abgebildet. Die Regeln werden vor der
Ruleset gelesen und funktionieren auch ohne eine. Zwei Endpunkte
schlagen vor, was zu setzen ist, und schreiben nichts:
[`detect-pagetype`](/de/api/applications/detectApplicationPageType)
nennt das Shop-System,
[`pagetype/discover`](/de/api/applications/discoverApplicationPageTypeRules)
findet die Klassennamen. Siehe
[Tracker → `pagetype_rules`](/de/tracker#pagetype-rules).

## Checkout-Funnel [#checkout-funnel]

Standardmäßig an, unter `shop.checkout`. Der Collector markiert jeden
Pageview, dessen URL auf ein Warenkorb-, Checkout- oder
Abschluss-Muster passt, und registriert die Warenkorb-Requests der
Shopseiten aus Fetch/XHR. `checkout_tracking` ist das Opt-out; die
drei Pfadlisten erben jeweils die eingebauten Muster (`null`) oder
ersetzen sie komplett. Die Markierung wirkt nur vorwärts, und
Besucher pro Stufe zu zählen braucht `store_stitch`. Ein
Shopify-Shop ergänzt seinen Checkout über das
[Pixel](/de/guides/shopify-checkout). Siehe
[Checkout-Funnel](/de/checkout-funnel).

## Per-Domain-Defaults

Drei Einstellungen sind Application-Level-**Defaults**, die jede
Mitglieds-Site erbt und pro Domain überschreiben kann:

- **`data_retention_days`** (Default `90`): wie lange Rohdaten
  behalten werden.
- **`store_stitch`**: den Edge-Besucher-`stitch` persistieren, der
  die Unique-Visitor-Zahlen treibt. Eine Site kann ihn selbst
  abschalten.
- **`count_visitors_by`** (`stitch` / `session`): nach welcher
  Kennung die **Visitors**-Metrik zählt. Zur Query-Zeit begrenzt auf
  das, was die Site speichert.

Eine Site erbt diese, solange sie keinen eigenen Wert setzt. Siehe
[Sites](/de/concepts/sites).

## Was eine Application hat [#application-fields]

Die Response gruppiert ihre Felder in `page_type`, `shop`, `collection`,
`collector`, `script` und `site_defaults`. Create und Update nehmen dieselben
Gruppen als Teilobjekte und lehnen jeden unbekannten Key ab. Die flachen
Zwillinge, die diese Gruppen ersetzt haben, antworten nicht mehr.

| Feld                         | Typ               | Hinweise                                                              |
| ---------------------------- | ----------------- | --------------------------------------------------------------------- |
| `id`                         | UUID v7           | Stabiler Identifier.                                                  |
| `organization_id`            | UUID v7           | Die besitzende Organisation.                                          |
| `name`                       | string            | Wie die Application im UI erscheint.                                  |
| `environment`                | enum              | `prod` oder `dev`. Default `prod`. Markiert Nicht-Produktions-Apps.    |
| `platform`                   | object · nullable | Shopsystem oder CMS: `key`, `source`, `detected_via`, `detected_at`.  |
| `shop.active`                | bool · nullable   | Ob das ein Shop ist. `null` folgt der Plattform.                      |
| `spa`                        | bool              | Single-Page-App. Von Hand gesetzt, Default `false`.                   |
| `collection.*`               | bool · enum       | Die Preset-Flags: Sessions, Fetch/XHR, Fehlermessages und -Frames, Query-Keys und -Werte, `session_consent`, `template_url_ids`. Siehe [Presets](/de/tracker). |
| `page_type.body_class`       | bool              | Page-Type aus der `<body>`-Klasse lesen. Default aus.                 |
| `page_type.rules`            | list · nullable   | Deine eigenen Body-Klassen, auf Page-Types abgebildet. Wird vor der Ruleset gelesen. |
| `shop.checkout.tracking`     | bool              | Checkout-Funnel an (`true`, der Default) oder aus. Siehe [Checkout-Funnel](#checkout-funnel). |
| `shop.checkout.*_paths`      | list · nullable   | URL-Muster pro Funnel-Stufe. `null` erbt die eingebauten Muster; eine Liste ersetzt sie. |
| `collector.mode`             | enum              | `default` / `relative` / `custom`.                                    |
| `collector.endpoint`         | string · nullable | Eigener Collector-Host (nur bei `custom`).                            |
| `collector.proxy_secret`     | object            | Das gemeinsame Secret für einen [First-Party-Proxy](/de/guides/first-party-proxy). |
| `script.source_hash`         | string            | Global eindeutig; in der Script-URL (`/s/{source_hash}.js`).          |
| `script.collector_hash`      | string            | Global eindeutig; in der Ingest-URL (`/c/{collector_hash}`).          |
| `script.source_version`      | string            | Gepinnte Beacon-Template-Version (`v1`).                              |
| `site_defaults.*`            | int · bool · enum | `data_retention_days`, `store_stitch`, `count_visitors_by`. Eine Site kann jedes überschreiben. |
| `site_policy`                | enum              | `open` / `auto` / `strict`. Umgang mit unbekannten Hostnamen.         |
| `is_active`                  | bool              | Bei `false` werden Beacons angenommen, aber nicht geschrieben.        |

Sechs Felder bleiben für das Shopware-Plugin flach: `source_hash`,
`collector_hash`, `proxy_secret`, `collector_mode`, `collector_endpoint`
und `pagetype_ruleset`.

## Sites: adoptieren, verschieben, löschen

- **Domain hinzufügen**: eine Site anlegen oder eine vorgeschlagene
  Domain adoptieren.
- **Site verschieben**: sie übernimmt die Config der neuen
  Application. Eine Domain gehört immer zu genau einer Application.
- **Site löschen**: entfernt die Daten dieser Domain, mit Bestätigung.
