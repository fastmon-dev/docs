A notification rule checks a metric of one production application on a schedule and alerts when its condition holds. This page also covers the channels it posts to and forwarding observations.

**Notifications** in the sidebar has three tabs: **Rules**, **Channels**, and **Observations**. The tab is part of the address, so a link opens it. Creating and changing rules and channels needs `notification:write`, which only owners hold. Members and viewers see the rules and their history.

## Channels [#channels]

A channel is a Slack, Discord, or webhook endpoint. You set it up once under **Channels → New channel** and pick it in any rule or observation forwarding.

| Field        | Meaning                                                                                                        |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| **Type**     | Slack, Discord, or Webhook.                                                                                    |
| **Name**     | How rules and lists show it, for example `#ops-alerts`.                                                        |
| **URL**      | An https URL that resolves to a public address: a Slack app's incoming webhook, a Discord channel webhook, or your endpoint. |
| **Language** | English or German, for every message the channel gets.                                                         |
| **Enabled**  | Off stops all posts to the channel.                                                                            |

After saving, the URL is never shown in full again. **Send test message** posts a test and shows whether the endpoint accepted it.

### Webhooks [#webhooks]

Webhook channels follow [Standard Webhooks](https://www.standardwebhooks.com). Any Standard Webhooks library verifies them.

- **Signing secret**: fastmon generates a `whsec_` secret when you create the channel and shows it once. **Rotate signing secret** replaces it, shows the new one once, and ends the old one at once.
- **Headers**: every request carries `webhook-id`, `webhook-timestamp`, and `webhook-signature`. `webhook-id` stays the same on every retry, so you can drop duplicates.
- **Body**: `{"type", "timestamp", "data"}`. `data` holds the organization, application, site, and channel references, the subject with its `id`, and a `message` with title, summary, language, and link.

To get the whole rule or observation, read it by its `id`. The published OpenAPI document lists the body schemas under `webhooks`.

| `type`                   | Sent when                                    |
| ------------------------ | -------------------------------------------- |
| `rule.firing`            | a rule's condition starts holding            |
| `rule.resolved`          | the condition stops holding                  |
| `rule.test`              | you send a test from a rule                  |
| `observation.opened`     | a forwarded observation opens                |
| `observation.occurrence` | a forwarded recurring shift occurs again     |
| `channel.test`           | you send a test message from the channel     |

## Create a rule [#create]

Open **Rules → New rule**. Pick a preset or **Start from scratch (custom)**, then edit any field.

| Preset                  | Condition                                                            |
| ----------------------- | -------------------------------------------------------------------- |
| **LCP regression**      | LCP p75 above 2,500 ms over 24 hours                                 |
| **CLS regression**      | CLS p75 above 0.1 over 24 hours                                      |
| **INP regression**      | INP p75 above 200 ms over 24 hours                                   |
| **Traffic drop**        | requests down by half or more against the 24 hours before            |
| **Error rate too high** | more than 1 % of pageviews with a first-party JavaScript error       |
| **Page weight bloat**   | transferred bytes p75 above 3 MB over 7 days                         |

### Scope and metric [#scope]

- **Application**: one production application. The rule pools all its active sites into one value, or watches one site of it. It sends one message however many sites it pools.
- **Metric and aggregation**: LCP, INP, CLS, TTFB, the error rates, pageviews, visitors, and the other analytics metrics, with p50, p75, p95, count, or avg. `visitors` and `requests` take `count` only.
- **Identity**: for `visitors` only, `stitch` (default, works in every mode) or `session` (consent-gated).
- **Filter**: optional, for example device type mobile, a URL pattern, or `country = DE`.

### Condition [#condition]

- **Window**: 1 hour, 6 hours, 24 hours, 7 days, or 30 days. fastmon checks the rule every fifth of the window, between 1 and 15 minutes.
- **Absolute**: the value is above or below a threshold, for example LCP p75 above 3,000 ms.
- **Relative change**: the value rises or drops by a percentage against the baseline window right before. In the API the threshold is a ratio: `-0.5` is a drop by half.

On a low-traffic site, a relative change over 24 hours is noisy. Widen the window to 7 days before you loosen the threshold.

### Targets [#targets]

**Send to** picks channels and **Members by mail**. Members get the mail in their own language, English or German. A rule needs at least one target.

## Firing and resolving [#firing]

- **A rule fires on the transition.** It sends when the condition starts holding, then stays silent while it holds.
- **Re-notify**: by default once per episode. Set 1 hour to 7 days to resend while the condition still holds.
- **Resolved**: when the condition stops holding, the rule sends a resolved message. An evaluation without data changes nothing.
- **Switching a rule on** starts it from a clear state.
- **Retries**: a 4xx answer other than 429 fails at once. Any other failure is retried for about 50 minutes.

## Test and history [#test]

**Evaluate now (dry-run)** runs the rule against the current window without sending anything. If it fires on every try, the threshold is too tight.

**Send a test to every target** sends a sample message through the saved rule. It is limited to 5 tests per organization in 10 minutes, and the pop-up then says how long to wait.

The test result and the **History** list every target with **Delivered** or **Failed** and the reason.

## Forward observations [#observations]

The **Observations** tab posts [observations](/en/observations) to a channel. **New subscription** creates one forwarding.

| Field                | Meaning                                                                  |
| -------------------- | ------------------------------------------------------------------------ |
| **Channel**          | Where the observations go. Fixed after creation.                         |
| **Observations of**  | One application, or **All applications**. Fixed after creation.          |
| **Directions**       | Degradation, Improvement, Neutral. Default: Degradation only, as in the mail. |
| **Metrics**          | Default: all metrics.                                                    |

A channel gets the same events as the observation mail, in its language, with a link to the observation. A failed post is retried for about an hour.

**Partner organizations** can forward their clients' observations: of one client, one of its applications, or **All clients**, including clients linked later. Only direct members of the partner see and set these up.
