          Create a synthetic page (URL normalized + must be under the site
          domain).


          Registering the CS site always kicks off exactly one immediate
          analysis — you

          can't create a CS site without it running once — so even a paused page

          (`schedule=false`) produces this one creation run; its `analysis_uuid`
          is returned

          so the client polls `analyses/{uuid}/status` instead of firing a
          redundant `run`.


          `mode=monitor` (default) is a sticky, quota-counted page honoring the
          schedule

          flags. `mode=oneshot` is an unbudgeted "measure now": schedules forced
          off,

          `nocache` forced true, and a missing creation-run id is fatal (502)
          rather than

          tolerated — the run *is* the deliverable. A one-shot stays viewable
          via the normal

          detail/run endpoints and can be promoted later via PATCH
          (source→manual + schedule).


          One-shot is intentionally **unbounded** (no quota) — note the cost: CS
          has no

          reliable teardown, so each one-shot on a *new* URL leaves a CS site we
          can't reap.

          Add a cap here once CS supports teardown.
