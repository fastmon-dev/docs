## Base URL

```
https://api.fastmon.eu/v1
```

Die öffentlichen Ingest-Endpunkte (`POST /c/{collector_hash}` und
`GET /s/{source_hash}.js`) liegen **außerhalb** des `/v1/`-Prefix und
haben einen eigenen Vertrag.

## Beispiel

```bash
curl https://api.fastmon.eu/v1/organizations \
  -H "Authorization: Bearer fm_$YOUR_TOKEN"
```

```json
{
  "data": [
    { "id": "01HZX…", "name": "Acme", "plan": "pro" }
  ],
  "meta": { "limit": 50, "offset": 0, "total": 1, "has_more": false }
}
```

## Konventionen

- **IDs sind UUID v7** — nach Erzeugungszeit sortierbar.
- **Zeitstempel sind ISO-8601 UTC mit `Z`** —
  `2026-04-18T12:34:56.123456Z`.
- **Einzelne Ressourcen** werden direkt zurückgegeben; **Listen**
  wrappen mit `data` + `meta`; **Fehler** wrappen mit `error`.
  Siehe [Fehler](/de/api/errors).
- **Default-Limit** 50, Max 100 auf jedem List-Endpunkt.
- **`X-Request-ID`** auf jeder Response. Beim Reporting
  zurückgeben.

## Versionierung

API-Version ist `v1`. Breaking Changes laufen als neuer Prefix
(`/api/v2`) — `v1` bleibt nach `v2`-Release mindestens 12 Monate
nebeneinander funktionsfähig.

Additive Änderungen (neue Felder, Endpunkte, Query-Parameter)
laufen kontinuierlich in `v1`. Clients sollten unbekannte Felder
ignorieren.

## Schema-Dokument

Das rohe OpenAPI-Dokument liegt unter
[`api.fastmon.eu/v1/openapi.json`](https://api.fastmon.eu/v1/openapi.json).
Direkt in `openapi-typescript`, `oapi-codegen` oder ähnliches werfen
für einen typisierten Client.
