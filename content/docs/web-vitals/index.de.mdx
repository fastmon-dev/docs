**Web Vitals** sind Googles Standardmetriken dafür, wie schnell und stabil sich eine Seite anfühlt, hier gemessen im Browser deiner echten Besucher. Diese Seite listet sie und die weiteren Metrik-Seiten in fastmon.

## Die fünf Metriken

LCP, INP und CLS sind die Core Web Vitals, die Google fürs Ranking nutzt. Mit FCP und TTFB findest du heraus, *warum* dein LCP langsam ist.

| Metrik                                                    | Was sie misst                                            | Gut (p75)  |
| --------------------------------------------------------- | -------------------------------------------------------- | ---------- |
| [LCP](/de/web-vitals/lcp), Largest Contentful Paint    | Zeit, bis das größte sichtbare Element rendert.          | ≤ 2.500 ms |
| [INP](/de/web-vitals/inp), Interaction to Next Paint   | Worst-Case-Latenz von Interaktion bis nächstem Paint.    | ≤ 200 ms   |
| [CLS](/de/web-vitals/cls), Cumulative Layout Shift     | Summe unerwarteter visueller Verschiebungen.             | ≤ 0,1      |
| [FCP](/de/web-vitals/fcp), First Contentful Paint      | Zeit, bis Text oder Bild erstmals erscheint.             | ≤ 1.800 ms |
| [TTFB](/de/web-vitals/ttfb), Time to First Byte        | Zeit, bis das erste Response-Byte ankommt.               | ≤ 800 ms   |

## Weitere Metrik-Seiten [#other-metric-pages]

Fünf weitere Seiten sind aufgebaut wie die LCP-Seite: der Wert mit Trend, die Pageviews nach Bewertung, eine Zusammenfassung, der Verlauf neben der Verteilung und wo die Metrik am schlechtesten ist.

| Seite                | Sidebar                 | Gut (p75)     | Schlecht (p75) |
| -------------------- | ----------------------- | ------------- | -------------- |
| TBT                  | Performance → TBT       | ≤ 200 ms      | > 600 ms       |
| Seitenladezeit       | Performance → Page load | nicht bewertet | nicht bewertet |
| DNS-Lookup           | Netzwerk → DNS          | ≤ 60 ms       | > 100 ms       |
| TCP-Verbindung       | Netzwerk → Connect      | ≤ 200 ms      | > 600 ms       |
| Übertragungsgröße    | Netzwerk → Transfer size | nicht bewertet | nicht bewertet |

- **DNS und Connect** zählen nur Pageviews, die wirklich einen Lookup gemacht (`performed_dns_lookup`) oder eine neue Verbindung geöffnet haben (`new_tcp_connection`). Die Zusammenfassung nennt ohne Bewertung, wie viele Pageviews den Lookup übersprungen oder eine Verbindung wiederverwendet haben.
- **TBT** listet die Skripte in Long Animation Frames über 50 ms, wie die INP-Seite.
- **Übertragungsgröße** teilt das Gewicht nach Ressourcentyp auf und listet die Drittanbieter-Domains. Sie zählt die Bytes, die ein Aufruf heruntergeladen hat, ein warmer Aufruf liest also leicht.
- **Seitengewicht** (`page_weight`) ist das Gewicht eines ersten Aufrufs, Browser-Cache-Treffer eingeschlossen: gut bis 2.667 KiB, schlecht über 4.000 KiB. Mit `browser_cache_bytes`, `browser_cache_saving` und `warm_view_rate` ist es eine Metrik im Explorer, in Filtern und in Alert-Regeln, keine Seite. Ein warmer Aufruf in Safari sendet keins.

Jede Bewertung kommt aus [`GET /metric-thresholds`](/de/web-vitals/experience-score#thresholds).

## Perzentile lesen

Web Vitals liest du auf dem **75. Perzentil**: 75 % der Pageviews im Zeitraum hatten einen besseren Wert, 25 % einen schlechteren. Liegt dein LCP bei p75 bei 2.400 ms, wartet das langsamste Viertel deines Traffics mindestens so lange.

## Wie fastmon sie erfasst

Der Tracker liest dieselben Browser-APIs wie die [`web-vitals`](https://github.com/GoogleChrome/web-vitals)-Library: `PerformanceObserver`-Einträge, Navigation Timing für TTFB und die Attribution-Daten des Browsers für INP. Jeder Wert steht zu seinem eigenen Zeitpunkt fest, meist wenn die Seite versteckt wird, und geht in wenigen Beacons pro Pageview raus. Siehe [Der RUM-Beacon](/de/concepts/beacon).

## Wo sie im Produkt auftauchen

- **Performance-Dashboard**: p50/p75/p95 pro Metrik, slicebar nach URL, Device, Land und Release.
- **Experience Score**: LCP, INP, CLS, FCP, TTFB und die eigene Fehlerrate als eine Zahl von 0–10. Siehe [Experience Score](/de/web-vitals/experience-score).
- **Notification Rules**: Alarm, wenn eine Metrik eine Schwelle überschreitet oder sich gegen das Vorfenster verschlechtert.
- **Analytics-API**: jede Metrik programmatisch abfragen. Siehe die [Analytics-Endpunkte](/en/api/analytics/queryAnalytics).

## Nächste Schritte

- Starte mit [LCP](/de/web-vitals/lcp), dann [INP](/de/web-vitals/inp): INP leidet oft, wenn ein LCP-Fix mehr JavaScript mitbringt.
- Für eine einzelne Zahl über Zeit: [Experience Score](/de/web-vitals/experience-score).
