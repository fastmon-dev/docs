---
title: Implement Fastmon on WordPress
description: Drop the beacon onto a WordPress site — with a header-injection plugin or by editing your theme.
---

WordPress doesn't ship a built-in slot for `<head>` snippets, so
you've got two sensible options: a header-injection plugin or a
small edit to your theme. Pick whichever your workflow already
uses.

**Time to first data:** about five minutes.
**You'll need:** Fastmon site credentials (see [the
overview](/en/install)) and admin access to your WordPress site.

## 1. Get your `source_hash`

Open the site you want to monitor in Fastmon. Copy the `source_hash`
from the site settings page — it looks like `a1b2c3d4`. The full
snippet you'll use is:

```html
<script src="https://api.fastmon.eu/s/{source_hash}.js" async></script>
```

## 2. Add the snippet

Two paths. Pick one.

### Option A: With a header-injection plugin (recommended)

Most WordPress sites already have one of these. If not, grab
**WPCode** (free, formerly "Insert Headers and Footers") — it's
the most widely used and stays out of your way.

1. In the WordPress admin, open **Plugins → Add new**.
2. Search for **WPCode** and click **Install Now**, then **Activate**.
3. Open **Code Snippets → Header & Footer**.
4. Paste the Fastmon `<script>` tag from step 1 into the **Header**
   field.
5. Click **Save Changes**.

The snippet now renders inside `<head>` on every front-end page.

### Option B: Editing your theme

This survives plugin removal — but it'll break the next time
someone re-uploads the theme.

1. In the WordPress admin, open **Appearance → Theme File Editor**.
2. Open `header.php`.
3. Paste the Fastmon `<script>` tag immediately before `</head>`.
4. Click **Update File**.

If you have a **child theme**, do this in the child theme's
`header.php` — safer that way. If your theme has no `header.php`,
it's probably using a hook-based header (common with block themes).
Then go with **Option A**.

## 3. Verify it works

Open any front-end page on your site, view source (`⌥⌘U` /
`Ctrl+U`), and search for `fastmon.eu`. The `<script>` tag must be
present in the HTML the browser actually receives — if it isn't,
the snippet wasn't injected.

Now open DevTools → **Network**, filter for `c/`, switch to another
tab, and come back. You should see a `POST` to
`https://api.fastmon.eu/c/{collector_hash}` with status `204`.

In Fastmon, open the site's dashboard. Within ~30 seconds the
**Traffic** section will show non-zero sessions.

If something is off, see
[Verifying it works](/en/install/verify).

## Notes

- **Multisite.** Repeat the setup per site, each with its own
  `source_hash`. Every WordPress site is a separate property in
  Fastmon.
- **Caching plugins.** Some caching plugins minify or rewrite
  `<head>`. If your snippet vanishes after you enable caching,
  exclude the Fastmon script from minification — most plugins have
  a per-script exclusion list.
- **Cookie banners.** The Fastmon beacon doesn't set cookies, so
  it doesn't need to sit behind your CMP. If your governance
  policy says otherwise, switch the site to
  [`consent` collection mode](/en/collection-modes#consent--wait-for-opt-in).
- **Page builders.** Don't paste the script into a page-builder
  content block — most strip unknown tags. Use Option A instead.
