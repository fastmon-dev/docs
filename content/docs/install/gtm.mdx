---
title: Implement Fastmon via Google Tag Manager
description: Drop the beacon onto a site managed through GTM — a single Custom HTML tag, fired on All Pages.
---

If your team manages tags through Google Tag Manager, the Fastmon
beacon goes in as a **Custom HTML** tag firing on every page.
There's no Fastmon-specific GTM template — the snippet is too
small to need one.

One caveat up front: GTM is a US-jurisdiction service. The
Fastmon beacon itself runs entirely in the EU, but loading it
*through* GTM puts a US loader on the critical path. If you want
a strictly EU-only path with no US-jurisdiction provider between
the visitor and our beacon, embed the script directly via the
[HTML guide](/en/install/html).

**Time to first data:** about five minutes.
**You'll need:** Fastmon site credentials (see [the
overview](/en/install)) and Edit/Publish access to the GTM
container that's already on your site.

## 1. Get your `source_hash`

Open the site you want to monitor in Fastmon. Copy the `source_hash`
from the site settings page — it looks like `a1b2c3d4`. The full
snippet you'll paste is:

```html
<script src="https://api.fastmon.eu/s/{source_hash}.js" async></script>
```

## 2. Create the tag in GTM

1. Open your GTM workspace and click **Tags → New**.
2. Name the tag **Fastmon Beacon**.
3. Click **Tag Configuration** and pick **Custom HTML**.
4. Paste the `<script>` snippet from step 1 into the **HTML** field.
5. Leave **Support document.write** unchecked. Leave the advanced
   settings at their defaults.

## 3. Add the trigger

1. Click **Triggering** and pick **All Pages** (the built-in trigger
   that fires on every Pageview).
2. Save the tag.

## 4. Preview, then publish

1. Click **Preview** to open Tag Assistant. Connect to your site URL
   and load any page.
2. In Tag Assistant, confirm **Fastmon Beacon** appears in the **Tags
   Fired** list.
3. Back in GTM, click **Submit**, give the version a name, and
   **Publish**.

## 5. Verify it works

Open a page on your live site, open DevTools → **Network**, filter
for `c/`, switch to another tab, and come back.

You should see a `POST` to `https://api.fastmon.eu/c/{collector_hash}`
with status `204`.

In Fastmon, open the site's dashboard. Within ~30 seconds the
**Traffic** section will show non-zero sessions.

If something is off, see
[Verifying it works](/en/install/verify).

## Notes

- **Page Load vs DOM Ready vs Window Loaded.** GTM's **All Pages**
  trigger fires on `gtm.js` (the earliest event). That's correct for
  Fastmon — earlier means more Web Vitals captured.
- **Consent Mode integration.** If you use GTM's consent feature and
  want the beacon to wait for consent, switch the Fastmon site to
  [`consent` collection mode](/en/collection-modes#consent--wait-for-opt-in).
  GTM's consent state then fires the `fastmon:consent` event when
  appropriate — bridge it with a small Custom HTML tag listening for
  GTM's `consent_update` event.
- **Multiple GTM containers on one page.** Add the tag to whichever
  container fires earliest. Don't add it twice; you'll double-count
  every page-view.
- **GTM "load" timing.** GTM itself adds latency before the beacon
  loads. On slow networks this delays the start of
  `PerformanceObserver` by a few hundred ms, which can cause a
  small under-count of very early entries on the first page-view.
  The HTML route avoids this.
