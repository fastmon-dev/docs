Fastmon ist ein gehosteter Dienst. Auf deinen Servern ist nichts zu
installieren: Du fügst ein einziges `<script>`-Tag ein und richtest es
auf deine Fastmon-Application. Etwa fünf Minuten Arbeit.

Ein Tag im `<head>` funktioniert auf jeder Seite, die du kontrollierst:
statisches HTML, Next.js, WordPress, Hugo oder über einen Tag-Manager.

## Wie das zusammenhängt

- Eine **Application** ist ein Tracking-Snippet. Ihr gehören die
  Erfassungseinstellungen und die Hashes, die das Snippet identifizieren.
- Eine **Seite** ist eine Domain unter dieser Application, mit eigenem
  Dashboard und eigenem Traffic.

Die meisten brauchen genau eine Application mit einer Seite, und Fastmon
legt dir beides an, wenn du deine erste Domain hinzufügst. Eine zweite
Seite an derselben Application brauchst du, wenn du mehrere Domains mit
einem Snippet betreibst. Eine zweite Application erst dann, wenn eine
Domain wirklich andere Erfassungseinstellungen benötigt.

## Was alle Setups gemeinsam haben

Das eingebundene Script ist byteweise dieselbe Datei, egal wie du es
lädst:

<InstallSnippet kind="script" />

`source_hash` identifiziert das Snippet deiner Application. Du findest
ihn zusammen mit `collector_hash` auf der Karte der Application unter
**··· → IDs & Hashes**. Öffnest du diese Seite über den
**Einrichten**-Button in der App, stehen oben automatisch beide Werte;
sonst kannst du sie in der
[Einbindungs-Anleitung](/de/install/html) eintragen.

Der Tracker:

- registriert `PerformanceObserver` für Web Vitals,
- puffert Events im Speicher und
- schickt gebündelte POSTs an `/c/{collector_hash}` über den
  Lebenszyklus des Seitenaufrufs: beim Laden, bei `pagehide`, bei
  `visibilitychange → hidden` und in periodischen Flushes.

Er setzt keine Cookies, speichert keine IPs und erstellt keinen
Fingerabdruck; die vollständige Aussage steht unter
[Datenschutz](/de/privacy).
