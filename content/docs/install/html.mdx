---
title: Implement fastmon on a website
description: Drop fastmon onto any website with a single script tag. Five minutes from sign-up to first data point.
---

The universal route: a single `<script>` tag in your `<head>`. It works on any site you control: static HTML, a Vue or React app, a Hugo blog, a Next.js project, a WordPress site, anything you can inject a `<script>` into.

**Time to first data:** about five minutes. **You'll need:** access to your site's HTML and a fastmon account.

## 1. Create a site in fastmon

Sign in, open the org you want to add this site to, and click **Create site**. Fill in:

- **Name**: whatever helps you recognize it later (e.g. `acme-marketing`).
- **Domain**: the bare hostname, no protocol. Example: `acme.com`.
- **Allowed origins** *(optional)*: leave blank to skip the origin check. If you set it, it becomes a strict allow-list; include the production domain too, as a comma-separated list (`acme.com, staging.acme.com, preview.acme.com`).

Leave the rest at defaults for now; you can come back to [collection mode](/en/collection-modes) and retention later.

Click **Save**. Fastmon generates two short hashes for the site:

- `source_hash`: goes into the script URL.
- `collector_hash`: used by the tracker to send data back. It's baked into the script, so you don't need to copy it.

Both show up on the settings page, along with a copy-paste-ready snippet; that's exactly what step 2 walks through.

## 2. Add the script to your site

Drop this single tag into the `<head>` of every page you want to monitor, with `{source_hash}` replaced by the hash from step 1:

```html title="<head>"
<script src="https://fastmon.site/s/{source_hash}.js" defer></script>
```

That's the whole setup. The tracker:

- registers `PerformanceObserver` for Web Vitals,
- buffers events in memory, and
- sends batched POSTs to `/c/{collector_hash}` over the page view's lifecycle: on load, on `visibilitychange → hidden`, on `pagehide`, and at periodic flushes. Expect a few per page view, not exactly one.

The tag uses `defer`: it loads in parallel with HTML parsing, never blocks the parser, and runs in source order once the DOM is parsed. `async` would also load without blocking, but it can interrupt parsing the moment the download finishes, and the order between multiple async scripts is whichever-finishes-first — for Web Vitals measurement we want predictable timing, so defer wins. Where you place it isn't critical, but `<head>` is the better spot; it lets the tracker catch the very first paint.

### Where to put it

| Site type                  | Put the tag in…                                              |
| -------------------------- | ------------------------------------------------------------ |
| Plain HTML / Hugo / Jekyll | `<head>` of your base template.                              |
| WordPress                  | A header-snippet plugin, or `header.php`.                    |
| Next.js / Nuxt / Astro     | The framework's head/script primitive (e.g. Next.js `<Script strategy="afterInteractive">` in `app/layout.tsx`). |
| Single-page apps           | The static `index.html` shell (once is enough).              |

## 3. Deploy and load a page

Push the change to production (or whichever environment you want to monitor) and open any page on the site in your own browser.

The tracker flushes periodically while the page is open, and again on `visibilitychange → hidden` and `pagehide`. Switching tabs or closing the page is the most reliable way to force a flush during testing, but it's not the only trigger.

## 4. Verify it works

Two checks: one in DevTools, one in the dashboard.

### In your browser

Open DevTools → **Network** → filter for `/c/`. You should see a `POST` to `https://fastmon.site/c/{collector_hash}`, either after the periodic flush ticks over, or when you switch tabs / close the page. Status 204 means the beacon was accepted.

If you don't see it, jump to [Verifying it works](/en/install/verify).

### In fastmon

Open the site in the dashboard. After about a minute (beacons are batched into ClickHouse), the **Traffic** section will show non-zero page views. (Sessions stay at zero in the default `anonymous` mode; that's expected. See [Sessions](/en/concepts/sessions).) The first beacon is the one you just sent; your IP isn't stored, but the row is there.
