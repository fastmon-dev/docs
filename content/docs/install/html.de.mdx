---
title: Fastmon auf einer Website implementieren
description: Fastmon mit einem einzigen Script-Tag auf jeder Website einbinden. Fünf Minuten vom Signup bis zum ersten Datenpunkt.
---

Der universelle Weg: ein `<script>`-Tag im `<head>`. Läuft auf
jeder Site, die du selbst hostest: statisches HTML, Vue/React,
Hugo-Blog, ein Next.js-Projekt, eine WordPress-Site, alles, wo du
ein `<script>` einbauen kannst.

**Zeit bis zu den ersten Daten:** etwa fünf Minuten.
**Was du brauchst:** Zugriff aufs HTML deiner Site und einen
Fastmon-Account.

## 1. Site in Fastmon anlegen

Logg dich ein, öffne die gewünschte Organisation und klick **Create site**.
Ausfüllen:

- **Name**: wie auch immer du sie später erkennst (z. B. `acme-marketing`).
- **Domain**: der reine Hostname, kein Protokoll. Beispiel: `acme.com`.
- **Allowed origins** *(optional)*: leer lassen, um Beacons von der
  Domain selbst zu akzeptieren. Staging- oder Preview-Hostnames hier
  als Komma-Liste eintragen (`staging.acme.com, preview.acme.com`).

Den Rest erstmal auf Default lassen; [Collection Mode](/de/collection-modes)
und Retention drehst du später bei Bedarf.

**Save** klicken. Fastmon legt zwei kurze Hashes für die Site an:

- `source_hash`: kommt in die Script-URL.
- `collector_hash`: nutzt der Beacon zum Senden. Steckt im Script
  drin, den musst du nicht extra kopieren.

Beide findest du auf der Einstellungsseite. Dort liegt auch ein
fertiges Snippet zum Reinkopieren; genau das, was im nächsten
Schritt erklärt wird.

## 2. Script auf deiner Site einbinden

Bau diesen Tag in den `<head>` jeder Seite ein, die du überwachen willst.
`{source_hash}` durch den Wert aus Schritt 1 ersetzen:

```html title="<head>"
<script src="https://fastmon.site/s/{source_hash}.js" defer></script>
```

Mehr ist es nicht. Der Beacon:

- registriert `PerformanceObserver` für Web Vitals,
- puffert Events im Speicher,
- schickt einen gebündelten POST an `/c/{collector_hash}` bei
  `visibilitychange → hidden`, bei `pagehide` und in periodischen
  Flushes.

Das Tag nutzt `defer`: lädt parallel zum HTML-Parsing, blockiert den Parser nie und läuft in Reihenfolge, sobald das DOM steht. `async` würde auch ohne Blockieren laden, kann das Parsing aber jederzeit unterbrechen, und die Reihenfolge zwischen mehreren async-Tags ist „wer zuerst fertig ist". Für Web-Vitals-Messung ist vorhersagbares Timing wichtig — deshalb defer. Wo du es
einbaust, ist relativ egal; der `<head>` ist trotzdem die bessere
Wahl, dann erwischt der Beacon auch den ersten Paint.

### Wo das Tag hinkommt

| Site-Typ                   | Tag einfügen in…                                              |
| -------------------------- | ------------------------------------------------------------- |
| Plain HTML / Hugo / Jekyll | `<head>` des Base-Templates.                                  |
| WordPress                  | Header-Snippet-Plugin oder `header.php`.                      |
| Next.js / Nuxt / Astro     | Das Head/Script-Primitive des Frameworks (z. B. Next.js `<Script strategy="afterInteractive">` in `app/layout.tsx`). |
| Single-Page-Apps           | Die statische `index.html`-Shell (einmal reicht).             |

## 3. Deployen und Seite laden

Pushe die Änderung nach Production (oder in die Umgebung, die du
überwachen willst), und ruf eine beliebige Seite im Browser auf.

Der Beacon flusht periodisch, solange die Seite offen ist, und
zusätzlich bei `visibilitychange → hidden` und `pagehide`.
Tab-Wechsel oder Schließen der Seite ist beim Testen der
zuverlässigste Weg, einen Flush zu erzwingen, aber nicht der einzige
Trigger.

## 4. Prüfen, ob es läuft

Zwei Checks: einer in DevTools, einer im Dashboard.

### Im Browser

DevTools → **Network** → nach `/c/` filtern. Du solltest einen
`POST` an `https://fastmon.site/c/{collector_hash}` sehen, entweder
nach dem periodischen Flush oder beim Tab-Wechsel / Schließen der
Seite. Status 204 bedeutet, der Beacon wurde akzeptiert.

Wenn nichts kommt: [Implementierung verifizieren](/de/install/verify).

### In Fastmon

Site im Dashboard öffnen. Nach ungefähr einer Minute (Beacons
werden in Batches in ClickHouse geschrieben) zeigt der
**Traffic**-Bereich Sessions &gt; 0. Der erste Beacon ist der, den
du gerade abgeschickt hast; deine IP behalten wir nicht, aber die
Zeile ist da.
