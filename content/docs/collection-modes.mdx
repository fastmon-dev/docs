title: Collection modes
description: Anonymous, consent, full. What they are, what they collect, and which one to pick.
---

Every fastmon site has a **collection mode**. It decides what the beacon actually does in the visitor's browser. Per site, switchable at any time; the script cache invalidates automatically.

Three modes: `anonymous`, `consent`, `full`. The default is `anonymous`, and for almost everyone that's the right pick.

## Compare at a glance

| Aspect                        | `anonymous` (default)              | `consent`                                                     | `full`                                  |
| ----------------------------- | ---------------------------------- | ------------------------------------------------------------- | --------------------------------------- |
| Default behavior              | Anonymous                          | Anonymous before opt-in, full after (toggled by your CMP)     | Full                                    |
| Storage on the visitor's device | None                             | None before opt-in; `_fm_consent` cookie + `sessionStorage._s` after | `sessionStorage._s` only            |
| Web Vitals                    | Yes                                | Yes                                                           | Yes                                     |
| Errors                        | Type, count, frame hosts + your own first-party script paths & line/col; no message | Same before opt-in; full frame detail + message after | Type + count + message + full frame detail |
| Cross-page `session_id`       | No (stripped)                      | No before opt-in, yes after                                   | Yes                                     |
| Referrer (bucketed source + medium) | Yes                          | Yes                                                           | Yes                                     |
| Raw referrer URL persisted    | Never                              | Never                                                         | Never                                   |
| LCP image URL, LoAF script paths, third-party domain map | Stripped | Stripped before opt-in; kept after                   | Kept                                    |
| Edge-derived `stitch` (bounded ≤24h, per-site) | Yes      | Yes                                                           | Yes                                     |
| Consent banner needed for our beacon | No (storage-free, no PII)      | No before opt-in; required for the opt-in path itself | Depends on your setup                   |
| When to pick it               | Everyone, unless you have a specific reason | You want Web Vitals from page 1 but session linkage only after CMP consent | You've decided session linkage is fine without an opt-in, or you're internal-only |

## `anonymous`: the default

The tracker sends right away on page load, no consent gate. It collects only the baseline fields listed in [Privacy](/en/privacy): nothing that could be used to identify a visitor across pages or sites.

**Pick this if:**

- you run a public website in the EU and want the simplest privacy posture. `anonymous` doesn't need a cookie banner *for our beacon*: it sets no cookies and stores no IPs. Other tools on the page may still need one, but that's not on us.
- you don't have a CMP integrated.
- you want to ship the setup without dragging engineering and legal into a meeting.

**What the tracker does:**

- Registers `PerformanceObserver` on page load.
- Buffers Web Vitals, errors, and resource timing in memory.
- Sends a batched POST on `pagehide` / `visibilitychange` / periodic flush.
- Mints a per-pageview ID that disappears with the page.

**What it doesn't do:**

- Set cookies.
- Read or write `localStorage` / `IndexedDB`.
- Touch form values or DOM content.
- Carry a `session_id`, LCP image URL, LoAF detail, or third-party domain map (all stripped before send).
- Try to identify the visitor. (One nuance: the edge derives a bounded, per-site `stitch` hash with ≤24h joinability and forward secrecy; see [Privacy](/en/privacy#the-edge-derived-stitch-identifier).)

## `consent`: let the page choose, controlled by your CMP

The site is configured for `consent`, and the wire shape each beacon uses is decided in real time by the visitor's consent state. Your CMP wires that state in with one of two calls:

```js
// In your cookie banner's "accept" handler:
window.__fastmon_consent(true);

// In the "reject" / "revoke" handler:
window.__fastmon_consent(false);
```

`__fastmon_consent(true)` sets a single `_fm_consent` cookie that persists the decision across pages, and unlocks the full wire shape (session id, LCP image URL, LoAF script paths, the third-party domain map, and error messages and frames). `__fastmon_consent(false)` deletes the cookie *and* clears the in-memory session id, so a previously-stitched session can't linger after opt-out. The call is idempotent; repeated calls with the same argument do nothing.

Until the visitor opts in, every beacon goes out **byte-identical to `anonymous` mode**: storage-free, no session id, no LCP image URL, no LoAF detail, no third-party domain map, error type + count only (no message, no frames). Web Vitals still flow. Consent unlocks **linkability**, not new categories of data.

The `_fm_consent` cookie does one thing — remember the consent decision so it survives a page navigation. That's the only reason it exists, and opt-out deletes it.

**Pick this if:**

- you want Web Vitals coverage even for visitors who never accept the CMP,
- but you also want session-level linkability (cross-page journeys, full URLs) only after explicit consent,
- you want one consent decision to govern fastmon along with other tools.

## `full`: keep everything the tracker collects, no consent gate

`full` keeps a handful of fields that `anonymous` strips:

- **`session_id`** so pageviews of the same session link together (cross-page journeys, funnels, return-visitor metrics). Lives in `sessionStorage`, dies with the tab.
- **LCP image URL** (origin + path, query and fragment stripped) for performance debugging.
- **Long Animation Frames (LoAF) detail**, including script paths (origin + path) for INP attribution.
- **Third-party domain map** so dashboard breakdowns show which vendor scripts contributed to load.
- **Error messages and full stack-frame detail.** Without consent the wire already carries the error type, count, every frame's host, and the path + line/column of frames in your own first-party external scripts. `full` adds the error **message** and the path/line/column of inline and third-party frames. The message still runs through the PII scrubber before transmission.

Everything else (Web Vitals, errors-by-type, browser / OS / device / viewport, connection type, RTT and downlink estimates, campaign attribution as UTM + click-ID label) is identical to `anonymous`. The privacy floor is also unchanged: no IP storage, no raw User-Agent, no static device-hint reads, no fingerprints.

What `full` gives up is the lean posture `anonymous` keeps: a stable cross-page identifier links pageviews into a real session — a bigger privacy step to take without asking the visitor first.

**Pick this if:**

- you're internal-only (intranet, employee app), where the visitor base and consent context look different,
- you've decided session linkage is fine without an opt-in step,
- you've signed a DPA that covers it explicitly.

If you're not sure, skip `full`. And if what you actually want is the opt-in gate, that's `consent`, not `full`. There's no upside to linking sessions you didn't have to.

## Two finer levers, independent of the mode

Beyond the mode, each site has two opt-out switches that cut identifiers without changing data categories:

- **`store_stitch`** (default on) — off makes the stored row genuinely anonymous: the edge-derived `stitch` is dropped in *every* mode, at the cost of unique-visitor and session metrics.
- **`store_session`** (default on) — off makes the served bundle skip `sessionStorage` entirely and drops `sid`, so a `full` / post-opt-in `consent` site keeps full content telemetry but no cross-pageview session id.

See [Privacy → Turning identifiers off entirely](/en/privacy#turning-identifiers-off-entirely) for the reasoning and [Sites](/en/concepts/sites) for where to set them. A third switch, `enforce_domain_match`, hardens ingest rather than privacy — see [Sites → Allowed origins](/en/concepts/sites#allowed-origins).

## Changing the mode

Open the site in fastmon, go to **Settings**, change **Collection mode**, save. The change takes effect when the script cache rolls over; usually within minutes for active visitors, immediately for new sessions.

You don't need to redeploy your site or change the `<script>` tag.
