---
title: Collection modes
description: Anonymous, consent, full — what they are, what they collect, and which one to pick.
---

Every Fastmon site has a **collection mode**. It decides what the
beacon actually does in the visitor's browser. Per site, switchable
at any time — the script cache invalidates automatically.

Three modes: `anonymous`, `consent`, `full`. The default is
`anonymous`, and for almost everyone that's the right pick.

## Compare at a glance

| Aspect                        | `anonymous` (default)              | `consent`                                                     | `full`                                  |
| ----------------------------- | ---------------------------------- | ------------------------------------------------------------- | --------------------------------------- |
| Default behavior              | Anonymous                          | Per-request via `?p=` (default anonymous)                     | Full                                    |
| Web Vitals                    | Yes                                | Yes                                                           | Yes                                     |
| Errors                        | Yes (no PII, fingerprinted)        | Yes                                                           | Yes                                     |
| Cross-page `session_id`       | No (stripped)                      | No before opt-in — yes after                                  | Yes                                     |
| Referrer                      | Stripped                           | Stripped before opt-in — kept after                           | Kept                                    |
| LCP image URL, LoAF detail, third-party domain map | Stripped     | Stripped before opt-in — kept after                           | Kept                                    |
| Cookie required               | No                                 | No (the `?p=` flag is a query param)                          | No                                      |
| GDPR consent banner needed for our beacon | No (no PII, no IP, no cookies) | Only required if you also want post-opt-in linkability | Depends on jurisdiction                 |
| When to pick it               | Everyone, unless you have a specific reason | You want Web Vitals from page 1 but session linkage only after CMP consent | You're under a regulator that explicitly permits richer collection, or you're internal-only |

## `anonymous` — the default

The beacon sends right away on page load — no consent gate. It
only collects what's listed in
[Privacy: what we don't collect](/en/privacy), so nothing that
could be used to identify a visitor across pages or sites.

**Pick this if:**

- you run a public website in the EU and want the simplest GDPR
  posture. `anonymous` doesn't need a cookie banner *for our
  beacon* — it sets no cookies and stores no IPs. Other tools on
  the page may still need one, but that's not on us.
- you don't have a CMP integrated,
- you want to ship the setup without dragging engineering and
  legal into a meeting.

**What the beacon does:**

- Registers `PerformanceObserver` on page load.
- Buffers Web Vitals, errors, and resource timing in memory.
- Sends a batched POST on `pagehide` / `visibilitychange` /
  periodic flush.
- Mints a per-page-view ID that disappears with the page.

**What it doesn't do:**

- Set cookies.
- Read or write `localStorage` / `IndexedDB`.
- Touch form values or DOM content.
- Carry a `session_id`, referrer, LCP image URL, LoAF detail, or
  third-party domain map (all stripped before send).
- Try to identify the visitor.

## `consent` — let the page choose, per request

The site is configured for `consent`, but the actual mode each
beacon uses is decided at request time via a `?p=` query parameter
on the collector URL:

- `?p=1` — the beacon ships as `full`.
- `?p=0` or no `p` at all — the beacon ships as `anonymous`.

Your CMP integration is responsible for setting that flag once the
visitor accepts. Beacons sent before consent (or after a revoke)
go out anonymously — Web Vitals still flow, but without `sid`,
without referrer, and with the same redactions as `anonymous`
mode. Consent unlocks **linkability**, not new categories of data.

**Pick this if:**

- you want Web Vitals coverage even for visitors who never accept
  the CMP,
- but you also want session-level linkability (cross-page journeys,
  full URLs) only after explicit consent,
- you want one consent decision to govern Fastmon along with other
  tools.

## `full` — keep everything the beacon collected, no consent gate

`full` keeps a handful of fields that `anonymous` strips:

- **`session_id`** so pageviews of the same session link together
  (cross-page journeys, funnels, return-visitor metrics).
- **Referrer** for source attribution.
- **LCP image URL** for performance debugging.
- **Long Animation Frames (LoAF) detail** for INP attribution.
- **Third-party domain map** so dashboard breakdowns show which
  vendor scripts contributed to load.

Everything else — Web Vitals, errors, browser/OS/device/viewport,
connection type — is identical to `anonymous`. The privacy floor
is also unchanged: no cookies, no IP storage, no raw User-Agent,
no fingerprints.

What `full` gives up is the GDPR-legitimate-interest argument that
`anonymous` rests on: a stable cross-page identifier turns
pageviews into a session, which is personal data under most
EU readings.

**Pick this if:**

- you're internal-only (intranet, employee app), where the
  visitor base and consent context look different,
- you're in a jurisdiction that explicitly permits session-level
  linkage without a separate basis,
- you've signed a DPA that covers it explicitly,
- or you've decided that `consent` is the better fit and you
  actually want the opt-in gate.

If you're not sure, skip `full`. Regulators aren't going to thank
you for linking sessions you didn't have to.

## Changing the mode

Open the site in Fastmon, go to **Settings**, change **Collection
mode**, save. The change takes effect when the script cache rolls
over — usually within minutes for active visitors, immediately for
new sessions.

You don't need to redeploy your site or change the `<script>` tag.
